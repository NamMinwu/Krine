# krine — 판단 일기 서비스 기획·설계 문서

작성일: 2026-08-20
상태: 확정 (구현 착수 기준 문서)

---

## 1. 한 줄 정의

> 하루의 일상 속에서 판단의 순간을 발견하고, 그 판단을 구조화·검증해 다시 꺼내 쓸 수 있게 하는 **판단 일기**.

일기는 UX의 껍데기이고, 제품의 핵심 객체는 **Judgment(판단)** 이다.
판단은 한 번 쓰고 끝나는 글이 아니라 **버전을 가진 살아있는 기록**이다. (판단 v1 → 반박 → v2 → 조건 변화 → v3)

## 2. 문제 정의

사람은 매일 결정을 내리지만, 그 결정을 만든 판단의 구조(전제·판단 기준·대안·근거)를 자신의 언어로 정리하고 검증할 기회가 부족하다. 그래서 자신의 판단을 설명하거나, 새로운 조건에 맞게 수정하고 재사용하기 어렵다.

**실패 지점 3개**

1. **결론만 남는다** — 무엇을 선택했는지는 기억하지만, 어떤 대안을 어떤 기준으로 비교했는지는 남지 않는다.
2. **검증 없이 넘어간다** — 반대 관점에서 전제를 공격받고 스스로 방어해보는 과정이 없다.
3. **판단이 축적되지 않는다** — 과거의 판단 기준과 조건을 다시 꺼낼 수 없어, 새로운 상황에서 참고하거나 수정할 수 없다.

**타깃**: 업무·일상에서 중요한 결정을 자주 내리고, 자신의 판단을 돌아보고 설명·수정하고 싶은 사람.

## 3. 솔루션 요구사항 (공유 기능 제외 버전)

| # | 요구사항 | 해결하는 실패 지점 |
|---|---|---|
| R1 | 판단이 있었던 순간을 떠올리게 한다 — 선택지·기준·포기한 것·변경 조건을 질문으로 끌어낸다 | 1 |
| R2 | 결론이 아니라 판단 구조를 남긴다 — 추출한 구조를 표/다이어그램으로 보여주고 사용자가 확인·수정한다 | 1 |
| R3 | 사용자가 직접 반박·재반박한다 — LLM은 다른 관점을 제시하되 답을 대신 쓰지 않는다 | 2 |
| R4 | 과거 판단을 다시 꺼내고 수정할 수 있다 — 조건이 바뀌면 이전 결론과 수정된 결론을 비교한다 | 3 |

공유(피드·투표·UGC)는 이번 범위에서 제외한다. 공유의 리텐션은 유저 수에 의존하는 외재적 루프이므로, 대신 **사용자 자신이 남긴 "판단 변경 조건"이 재방문을 만드는 내재적 루프**(재검토 루프)를 리텐션의 축으로 삼는다.

## 4. Core Loop

```
일상 회상 → 판단 발견 → 기록(적응형 질문, 한 번에 하나)
→ 구조화(Judgment Map, 사용자 승인) → 반박·재반박(Challenge, 옵트인)
→ 판단 카드 확정(불변) → 아카이브
→ [시점형 조건 도래 / 사건형 조건 체크인 / 보류한 반론] → 재검토
→ 재판단(유지·수정·뒤집음 = 새 버전) → 아카이브
```

### 재검토 루프의 대상 (확정 결정)

- **A. 판단 변경 조건**: 구조화 시 LLM이 각 조건을 분류한다.
  - **시점형**: 날짜로 환원 가능("약정 5개월 남음" → 만료일). 해당 날짜에 자동으로 재검토 큐에 올라간다.
  - **사건형**: 발생 여부를 사용자만 아는 사건("기기 고장"). 홈 체크인에서 "이 조건 중 발생한 것이 있나요?"로 묻는다.
  - 시점형 조건이 하나도 없는 판단은 저장 시 "30일 뒤에 다시 볼까요?"를 **제안**하고 사용자가 확정한다. (검증된 재검토 주기 30~60일 / AI가 자동 설정하지 않는다는 원칙)
- **C. 미해결 반론**: Challenge에서 사용자가 "보류"한 반론이 재검토 큐에 함께 쌓인다.
- B(결과 확인·예측 채점)는 범위에서 제외 — 문제 정의의 핵심이 "판단 평가"가 아니라 "판단 설명·수정"이기 때문.

### 불변 원본 원칙 (사후 확신 편향 방어)

확정된 판단 카드는 수정 불가. 재검토는 원본을 편집하지 않고 **새 버전**(유지/수정/뒤집음 + 이유)만 추가한다. Git 커밋과 같은 모델.

## 5. 레퍼런스 리서치 반영 (2026-08-20 조사)

| 레퍼런스 | 가져온 것 |
|---|---|
| Mindsera | 질문 하나씩 진행되는 프레임워크 스캐폴딩 / AI는 답이 아니라 "제안된 질문"만 제공 / 공감·진단이 아닌 분석 톤 |
| Rosebud | 사용자의 말을 따라가는 적응형 후속 질문(관점+질문 1개) / 깊이 탐색은 명시적 옵트인("Dig Deeper") |
| Stoic | 하루를 돌아보는 ritual로서의 홈 / 빈 화면 없는 진입 / 차분한 여백 |
| Decision Journal (FS) | 판단 정보구조(상황·대안·기준·조건·리뷰 시점) / 상태 기반 홈(검토 대기→예정→과거) / 원본 불변 / "재검토가 선택사항이면 실패" |
| Day One | On This Day식 시점 기반 재표면화 / 단일 아카이브 + 태그·기준별 필터 (다중 저널 분리 거절) |
| Heptabase | 판단 구조의 노드형 시각화 — 단, 사용자가 노드를 배치하지 않고 LLM이 구조화 → 사용자가 수정 |
| Daylio | 선택지 버튼 + 자유 입력을 섞은 가벼운 입력 |

**명시적으로 거절한 패턴** (README "안 만든 이유" 재료)

- 스트릭·연속 기록 배지 — 깊이 중심 제품에 피상적 참여 유인. 신규 사용자 이탈도 못 막음 (Stoic 리뷰 근거)
- AI 멘토 페르소나 — 판단을 외부 권위에 미루게 함. "자기 기준 강화"와 정반대
- AI 생성 주간 요약 — 기록의 소유권이 AI로 넘어감. 리포트는 원시 데이터+차트 중심으로만 (목업)
- 다중 저널 분리 — 판단 패턴 비교 불가. 단일 아카이브 + 태그
- ChatGPT형 채팅 UI / 복잡한 대시보드 / 화려한 그래프 / "사고 점수 82점"식 평가 — "당신의 판단은 72점입니다"가 아니라 **"당신의 판단을 이렇게 이해했습니다"**

## 6. UX 설계 (모바일 웹, 세로 단일 컬럼)

### 네비게이션

- 하단 탭 2개: **홈 / 아카이브**
- 기록 → 구조화 → Challenge는 탭이 아닌 **풀스크린 스텝 플로우** (한 화면 한 단계, 진행 표시 `2/5`)
- 채팅 말풍선 UI를 쓰지 않는다. 각 스텝은 "질문 + 입력"의 문서형 화면 — ChatGPT clone처럼 보이지 않게.

### 화면 1 — 홈 (하루를 돌아보는 ritual)

```
Good evening.
오늘 하루를 돌아볼까요?

🔔 재검토가 도착했어요 (1)
┌ 📱 휴대폰을 지금 바꿀까?
│ "약정 만료"로 설정한 날이 되었어요 → [다시 보기]

오늘 어떤 선택을 했나요?
[답장을 보냈다] [회의에서 의견을 골랐다] [구매를 고민했다] [일을 미뤘다]
[✍️ 판단 기록하기]

내 판단  검토 대기 1 · 완료 27
📱 휴대폰을 지금 바꿀까?  3일 전
💼 이 제안을 받아들일까?  7일 전
```

- 재검토 카드 최상단(재방문의 이유), 새 기록 유도 중간, 최근 판단 하단.
- 상태 구분: 검토 대기(Due) → 검토 예정(Scheduled) → 과거 판단(Past). (Decision Journal 정보구조)
- 작성 중 이탈한 판단이 있으면 "이어서 하기" 카드 표시. (모바일 웹 세션 이탈 대응)
- 스트릭 없음. 진행 증거는 "검토 대기 n · 완료 n" 카운트만.

### 화면 2 — 기록 (Step 1~2: 일기 → 적응형 질문)

- **Step 1 — 일기**: "오늘 어떤 선택을 했나요?" + 자유 서술 텍스트영역. 빈 화면 부담을 줄이는 회상 칩.
- **판단 발견**: 사용자가 그냥 하루 얘기를 쓰면 LLM이 판단 후보를 제안 — "이 이야기는 '기존 방식 유지 vs 새 방식 도입' 판단으로 기록해볼 수 있어요. [좋아요/아니요]"
- **Step 2 — 적응형 질문**: 빠진 조각(대안·기준·포기한 것·변경 조건)만 골라 **한 번에 하나씩**, 세션당 최대 4개. 선택지 버튼 + 직접 입력 병행. 진행 표시 `2/5`.
- 고정 설문 금지. 사용자의 직전 답을 반영해 다음 질문을 고른다. (Rosebud 패턴)

### 화면 3 — 구조화 (Step 3: Judgment Map)

- LLM이 추출한 구조를 "제가 이해한 게 맞나요?" 톤으로 제시. 모든 요소에 ✏️ 수정 (탭 → 바텀시트 편집).
- 시각화 2종 구현:
  - **선택지 비교표** — 얻는 것 / 포기하는 것 / 핵심 전제 / 판단 기준. 선택지 2개까지 2열 표, 3개 이상은 가로 스와이프.
  - **판단 트리(간이)** — 상황 → 선택지 분기 → 핵심 전제 → 현재 판단. Heptabase식 노드 시각화의 읽기 전용 축약판. LLM이 배치, 사용자는 내용만 수정.
- 변경 조건에 시점형/사건형 뱃지 표시. 시점형은 재검토 예정일 자동 표시.
- 저장(확정) 시 카드는 잠긴다 — 이후 수정은 새 버전으로만.

### 화면 4 — Challenge (Step 4: 반박·재반박, 옵트인)

- 구조화 후 자동 시작하지 않음. `⚔️ 다른 관점에서 검토해보기 — 건너뛰어도 좋아요` 버튼.
- 반론은 **하나씩**, 관점 라벨과 함께("비용을 가장 중요하게 본다면?"). 사용자가 자유 텍스트로 답변.
- LLM은 답변에서 드러난 기준을 되비추고, 후속 질문으로 변경 조건을 구체화한다. 답을 대신 쓰지 않는다.
- 각 반론의 종결: **[방어했다] [판단을 수정한다] [보류]** — 보류는 재검토 큐로.
- MVP: 반론 1~2개.

### 화면 5 — Reflection & 판단 카드 (Step 5)

- 저장 전 마지막 화면에서 **처음 표현 vs 지금 표현**을 나란히 보여준다:
  - 처음: "그냥 사고 싶어서 산다" → 지금: "비용보다 현재 사용 불편을 더 중요하게 평가하기 때문에 구매한다"
  - 결론이 안 바뀌어도 성공 — 판단이 명확해진 것을 보여주는 것이 목적.
- 판단 카드 = 일기 한 편: 상황 / 선택 / 핵심 기준 / 포기한 것 / 전제 / 변경 조건 / 검토한 반론과 나의 답 / 현재 판단.

### 화면 6 — 아카이브

- 단일 목록 + 필터: 주제 태그(업무/구매/관계…) · **판단 기준별**(비용/편의/안정성/성장) · 상태 뱃지(유지 ✓ / 수정됨 ↻ / 뒤집음 ⤴ / 검토 대기 ⏰).
- 카드 상세: 버전 타임라인(판단 변화 기록) + "당시 조건 vs 지금" 재검토 진입.

### 재검토 플로우

1. 홈 상단 카드 → "'다음 분기 일정 여유가 생기면 다시 본다'고 하셨어요. 지금은 어떤가요?" [조건이 발생했다 / 아직이다]
2. "아직이다" → 다음 재검토일 재설정 제안. "발생했다" → 재판단: **유지 / 수정 / 뒤집음** + 이유 입력 → 새 버전 생성.
3. 보류한 반론도 같은 큐에서 "그때 답 못 한 반박, 지금은요?"로 처리.
4. 재검토는 큐를 한 번에 들이밀지 않고 **카드 하나씩** 처리. (검토 피로 방지)

### 모바일 웹 제약 대응

- 푸시 알림 없음(iOS는 PWA 설치 시에만) → 재검토 트리거는 "앱을 열면 홈 최상단에 도착해 있다"로 성립. 서버는 날짜 기준으로 큐만 계산.
- 푸시·이메일 리마인더는 운영 확장 항목으로 문서화만.
- 스텝 플로우 진행 상태는 서버 저장 → 브라우저 이탈 후 "이어서 하기".

## 7. 디자인 방향

**Calm Journal × Structured Thinking**

- Stoic/Day One의 여백과 차분함 + Mindsera의 구조화 + Heptabase의 시각적 사고.
- 배경 오프화이트, 가독성 높은 산세리프, 절제된 색. 상태·뱃지 외 장식적 색 금지.
- CTA는 명확한 행동 동사(수정 / 검토하기 / 보류). 모호한 옵션 금지.
- 정신건강 앱처럼 보이지 않기. 판단을 평가하는 뉘앙스 금지.

## 8. LLM 설계

### 역할 분리 (프롬프트 4종)

| 역할 | 입력 | 출력 | 원칙 |
|---|---|---|---|
| 발견자 Discoverer | 자유 서술 | 판단 후보(제목, A vs B) | 하루 얘기에서 판단을 발견해 제안만 |
| 질문자 Questioner | 대화 이력 + 지금까지 채워진 구조 | 다음 질문 1개 + 선택지 | 빠진 조각만, 한 번에 하나, 최대 4개 |
| 구조화 Structurer | 전체 대화 | 판단 구조 JSON (+ 조건의 시점형/사건형 분류, 시점형은 날짜 추출) | "제가 이해한 게 맞나요?" — 확정은 사용자 |
| 반박자 Challenger | 확정된 판단 구조 (+ 사용자 답변) | 관점 라벨 + 반론 질문 1개 / 답변 되비추기 | 답 대필 금지 |

### 톤 가드레일 (모든 역할 공통, 시스템 프롬프트에 명문화)

- 공감 금지: "힘든 선택이겠네요" ❌
- 진단 금지: "그건 확증 편향이에요" ❌
- 평가 금지: "당신의 판단은 합리적입니다" ❌ / 점수화 ❌
- 허용: 분석 질문("이 선택의 최악의 경우는 무엇인가요?"), 되비추기("비용보다 현재 불편을 중요하게 보시는군요. 맞나요?")

### Provider 추상화

- `LlmPort` 인터페이스 뒤에 구현체를 둔다. 기본 **Gemini**, 설정으로 **OpenAI(GPT-4)** 교체 가능.
- API 키는 `.env` 관리, 저장소에 커밋하지 않는다.
- LLM 응답은 JSON 스키마 검증 후 사용. 실패 시 1회 재시도 → 사용자에게 수동 입력 폴백.

## 9. 데이터 모델 스케치

```
Decision (판단)
├─ id, title, situation(상황), topicTag, createdAt
├─ status: DRAFT(작성 중) | ACTIVE(확정) 
├─ versions: DecisionVersion[]      // 불변, append-only
│   ├─ versionNo, conclusion(현재 판단), verdict: INITIAL|MAINTAINED|REVISED|REVERSED
│   ├─ reason(수정 이유), createdAt
├─ options: Option[]                // 선택지
│   ├─ label, gains[], sacrifices[], premises[]
├─ criteria: string[]               // 판단 기준
├─ conditions: Condition[]          // 판단 변경 조건
│   ├─ text, type: DATE|EVENT, dueDate?, status: PENDING|TRIGGERED|DISMISSED
├─ challenges: Challenge[]          // 반박 기록
│   ├─ perspective, objection, userAnswer, resolution: DEFENDED|REVISED|DEFERRED
└─ conversation: Message[]          // 기록 플로우 대화 (이어서 하기용)
```

- 재검토 큐 = `Condition(type=DATE, dueDate<=today, status=PENDING)` + `Condition(type=EVENT, status=PENDING)` 체크인 + `Challenge(resolution=DEFERRED)`.
- 원본 불변: DecisionVersion과 Challenge는 UPDATE 없이 INSERT만.

## 10. MVP 범위

### 구현 (오늘)

1. 홈: 재검토 큐 + 회상 칩 + 최근 판단 + 이어서 하기
2. 기록 스텝 플로우: 자유 서술 → 판단 발견 → 적응형 질문(1개씩, 최대 4)
3. 구조화: 비교표 + 셀 수정 + 조건 시점형/사건형 분류 + 기본 재검토일 제안
4. Challenge: 반론 1~2개 + 3택 종결
5. Reflection: 처음 vs 지금 + 판단 카드 저장
6. 아카이브: 목록 + 태그/상태 필터 + 카드 상세(버전 타임라인)
7. 재검토: 큐 → 조건 확인 → 유지/수정/뒤집음 → 새 버전
8. 시드 데이터: 판단 3~4건, 그중 1건은 **만료일이 지난 시점형 조건** 포함 → 실행 즉시 재검토 큐가 보인다
9. LLM: Gemini 연동 + LlmPort 추상화 + 톤 가드레일

### 기획·목업 대체 (README에 구분 명시)

- 판단 트리 시각화의 완성형(현재는 간이 읽기 전용) — Heptabase식 캔버스는 로드맵
- 판단 패턴 리포트 — mock 데이터 화면. AI 요약이 아니라 원시 데이터+차트 중심
- 사건형 조건의 정기 체크인 스케줄링(주기 설정) / 푸시·이메일 리마인더
- 계정·인증 (MVP는 단일 사용자)
- 관리자 화면 — 운영 관점 문서로 대체 (LLM 호출 실패율·판단 생성 수 등 지표 정의)

## 12. 심사 3관점 매핑

- **핵심 가치 플로우**: 기록 → 구조화 → 검증 → 카드 확정. "결론만 남는다/검증 없이 넘어간다"를 직접 해결하는 최소 경로.
- **운영을 성립시키는 기능**: 재검토 루프(시점형 조건 자동 도래 + 사건형 체크인 + 보류 반론). 콘텐츠(판단 카드)가 쌓이고, 쌓인 콘텐츠가 재방문을 만든다.
- **관리·데이터 관점**: append-only 버전 모델로 데이터가 훼손 없이 축적. LLM 비용·실패율, 판단 생성/재검토 전환율이 핵심 지표. (관리자 화면은 문서로 대체)
